Yes — this is a very common real-world resume parsing issue, especially with PDFs.

Your extraction pipeline is likely extracting only **visible plain text URLs** like:

* `linkedin.com/in/yunlong-jiao/`

But not extracting:

* LinkedIn icons with embedded hyperlinks
* Text labels like `Narendra Analytics`
* Hidden clickable hyperlinks behind icons/text
* Hyperlinked SVG/image elements in PDFs

This is normal behavior if your parser currently uses only:

* `pdf-parse`
* raw text extraction
* OCR/text layer extraction

Because those tools mainly read the PDF text layer, not hyperlink annotations.

In resumes, many candidates use formats like:

* LinkedIn icon → clickable URL
* `LinkedIn` word → hidden hyperlink
* `Narendra Analytics` → hyperlink attached
* icons from Canva/Figma/Word resumes
* tables/columns with embedded links

Those links exist inside PDF annotations, not normal text content.

Example:
Visible text:

```text
Narendra Analytics
```

Actual embedded hyperlink:

```text
https://linkedin.com/in/narendra-analytics
```

Your current extraction probably sees only:

```text
Narendra Analytics
```

and misses the actual URL.

This especially happens with:

* Canva-generated resumes
* MS Word exported PDFs
* Figma resumes
* modern ATS-friendly templates
* icon-based contact sections

Even many ATS systems lose hyperlinks sometimes. ([Reddit][1])
