1. Project Overview
1.1 Project Title
Pratibha AI - Autonomous AI Recruitment & Hiring Agent Platform

1.2 Project Description
Pratibha AI is a production-grade multi-agent SaaS platform that acts as a fully autonomous senior recruiter. A hiring manager posts a job and uploads candidate resumes - the system then independently researches, evaluates, scores, and delivers a ranked shortlist report with zero manual effort.

The platform is built using Google Agent Development Kit (ADK) with a hierarchical multi-agent architecture. At the center is an Orchestrator Agent that routes tasks to 9 specialized agents, each responsible for a single, clearly defined step of the recruitment pipeline. The system uses a mixed-model strategy - Gemini 3.1 Pro for complex reasoning tasks and Gemini 3.1 Flash / Flash-Lite for high-volume extraction and scoring tasks - ensuring both quality and cost efficiency.

The frontend is built in Next.js 15 with Clerk authentication, Neon PostgreSQL with Drizzle ORM for data persistence, and Resend for email delivery. All Google ADK agents are written in TypeScript and run directly inside Next.js API routes - there is no separate backend server. The entire project is a single Next.js monorepo deployed to Vercel. The final output is a ranked candidate shortlist with explainable AI decisions, delivered as an interactive dashboard, downloadable PDF report, and optional email notification.

1.3 Mission Statement
To empower recruiters with autonomous AI agents that save time, reduce hiring bias, and ensure you hire the right talent, every time - with explainable, auditable decisions that keep humans in control.

1.4 Key Features
• 10-agent multi-agent orchestration using Google ADK hierarchical tree
• Parallel resume processing - multiple resumes evaluated simultaneously
• GitHub & portfolio analysis via GitHub REST API v3
• Culture & behavioral fit scoring from career trajectory signals
• Fraud detection - timeline inconsistencies, skill inflation, fake claims
• Structured Hiring Blueprint from raw job descriptions
• Explainable AI decisions - WHY each candidate is recommended
• Recruiter dashboard with ranked candidate list and score breakdowns
• Downloadable PDF reports + email delivery via Resend
• Human-in-the-loop approval - approve, reject, or adjust rankings
• Full audit trail of all agent runs and human overrides in Neon DB
• Mixed Gemini model strategy for cost efficiency at scale

3. Multi-Agent Workflow
3.1 How It Starts - User Actions
The hiring manager performs only two actions to initiate the full pipeline:
Step 1 - Create a Job Post:
• Job Title (e.g. Senior React Developer)
• Job Description (full JD text)
• Required Skills (tags - React, TypeScript, Node.js)
• Experience Level (Junior / Mid / Senior)
• Culture Notes (e.g. fast-paced startup, remote-first, collaborative)
• GitHub Evaluation Toggle (ON / OFF)
Step 2 - Upload Resumes:
• One or multiple resume files in PDF or DOCX format
• Files are stored in UploadThing / ImageKit with secure URLs
• The full agent pipeline triggers automatically after upload

4. Gemini Model Mapping
Pratibha AI uses a mixed-model strategy to balance quality and cost efficiency:
AgentsModelReasonOrchestrator Agent + Job Intelligence + Decision AgentGemini 3.1 ProComplex reasoning, planning, orchestration - Pro-level intelligence requiredTechnical Validation AgentGemini 3.1 FlashGitHub API analysis - reasoning needed, Flash handles efficientlyCandidate Extraction, Verification, Behavioral Alignment, Aggregator, Report GeneratorGemini 3.1 Flash-LiteRepetitive structured extraction, high-volume, low-latency tasks
4.1 Why Not Use Pro Everywhere?
A common developer mistake is using Gemini Pro for every agent. This approach:
• Increases API cost by 3-5x unnecessarily
• Increases latency per agent call significantly
• Reduces throughput when processing multiple resumes
The correct enterprise pattern: use Pro only where complex reasoning, planning, or explainability is critical. Use Flash-Lite for high-volume, structured extraction where speed matters more than depth.

8.1 Key Relationships
• jobs → candidates (one job has many candidates)
• jobs → hiring_blueprints (one job has one blueprint from Job Intelligence Agent)
• candidates → evaluations (one candidate has one evaluation per job)
• jobs → agent_runs (all agent executions are linked to a job for debugging)
• jobs → reports (one final report per job)
• candidates → overrides (hiring manager actions logged per candidate)

11. Security & Compliance Considerations
These must be implemented before any enterprise client demo:
• Principle of least privilege - each agent only accesses the data it needs
• Full agent run audit logging - every agent action stored in agent_runs table
• Human override required - no automated hiring decision without human approval (EEOC compliance)
• Resume data encryption at rest in Neon DB
• Secure file URLs - UploadThing generates signed, time-limited URLs
• GitHub token stored server-side only - never exposed to frontend
• Clerk JWT verification on all API routes
• Bias detection note in report - the system flags when scoring confidence is low
